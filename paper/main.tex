\begin{abstract}
Clinical agents now read records, order tests and write notes, and every step they take is a decision generated by a
large language model (LLM) after thousands of tokens of reasoning. System One decision models make a decision in a
single forward pass: they read a state and a set of options and return a probability for each. We ask whether such a
model can take the decision seat inside real clinical agent loops. We hold everything else fixed: the backbone (Clef-27B
is post-trained from Qwen3.8-27B, our LLM), the benchmarks' own loops, tools and graders, and the hardware. On
PhysicianBench, 100 consultation tasks run against an electronic health record of real de-identified patients, a System
One model that chooses among five turns proposed by the LLM matches the LLM: \PBcpSel\% of graded checkpoints versus
\PBcpLLM\%, with no significant difference in task success. It is the more decisive actor. When a required order is among the proposals, it
places it in \ONReqclef\% of cases; the LLM's own sample does so in \ONReqfirst\%. Asked instead to steer the agent,
choosing which tool to use next, the same model stops gathering evidence too early and passes only \PBcpTool\% of
checkpoints, while the LLM making that same restricted choice loses almost nothing. Step-level
analysis on MIMIC-IV admissions shows what limits selection: the LLM's samples are usually the same decision in other
words. Our results point to a clean division of labour. The LLM proposes and gathers; a System One model decides among
concrete actions.
\end{abstract}

\section{Introduction}

A physician's agent takes dozens of steps per task: look up the problem list, pull the labs, read last month's note,
order the imaging, write the assessment. Each step is a choice among a small set of concrete actions, and in today's
systems an LLM makes every one of them by generating text \citep{physicianbench2026,clinenv2026,yao2023react}. Figure~\ref{fig:case} follows one such task.

\emph{System One} decision models offer a different way to choose \citep{typesafe2026jev,clef2026}. They take a
state and a typed question with named options and return a probability for every option in one forward pass, with no
generated text and nothing to parse. They are fast, cheap and well suited to choosing among options, the operation an
agent performs at every step. Whether they can make an agent's decisions is open. So far they have been studied on
single-shot tasks and as judges \citep{li2026jevjudge}, and in general-purpose agent loops their actions often go wrong
even when they read the state correctly \citep{li2026reading}. No study has placed one in the decision seat of a
clinical agent.

We do so under the strictest comparison we can construct. Clef-27B is post-trained from Qwen3.8-27B, which serves as
our LLM, so the two decision makers share a backbone and differ in how they read out a decision. We run two clinical
benchmarks in their own harnesses, with their own tools, simulators and graders, and change only the component that
picks the next turn (Figure~\ref{fig:overview}). The System One model either chooses among complete turns proposed by
the LLM (\sel) or chooses only the kind of action, leaving the LLM to write it (\tool).

\paragraph{Findings.}
\begin{itemize}[leftmargin=*,itemsep=2pt,topsep=2pt]
  \item \textbf{A System One model can make the agent's decisions.} On PhysicianBench, \sel{} passes \PBcpSel\% of
  graded checkpoints against the LLM's \PBcpLLM\% ($\Delta$ \PBdiffSel{} points in task success), with no extra
  generated text from the decider (\S\ref{sec:select}).
  \item \textbf{It acts when action is required.} When one of the proposed turns places an order the task requires,
  the System One model takes it in \ONReqclef\% of steps, against \ONReqfirst\% for the LLM's own sample; when no
  required order is on offer, it orders far less often (\ONNoneclef\%). Action-execution checkpoints move by
  \PRSelLLMAE{} points (\S\ref{sec:act}).
  \item \textbf{It should not steer alone.} Choosing the tool for the LLM, the same model cuts data retrieval from
  \TLRetLLM{} to \TLRetTool{} calls per task and writes the note \TLDocTool{} times; checkpoint success falls to
  \PBcpTool\%. A control with the same one-tool restriction but the LLM choosing stays within noise of the LLM (\PRCtlLLMcp{} points), so
  the loss lies in the System One model's choices (\S\ref{sec:steer}).
  \item \textbf{Other System One models behave the same way.} On one fixed exam of logged states and proposals,
  pplx-decider-v1.2 and d3 take every required order on offer, as Clef does, while the LLM's own sample takes half;
  online, pplx-decider-v1.2 again matches the LLM when selecting and falls behind when steering
  (\S\ref{sec:deciders}; preliminary).
  \item \textbf{Selection is bounded by what the proposer samples.} On MIMIC-IV admissions, \CEOneDecision\% of the
  LLM's five-sample candidate sets contain a single clinical decision, and both deciders follow the proposer's
  hypothesis even when the gold decision is added (\S\ref{sec:diversity}).
\end{itemize}

\section{Putting a System One model in the decision seat}\label{sec:protocol}

An agent loop alternates between a state $s_t$, the task plus every action and result so far, and the next turn
$a_t$: a set of tool calls with arguments, or a final answer. The benchmark samples $a_t \sim \pi(\cdot\mid s_t)$ from
the LLM. We replace only this step.

\paragraph{\llm{} (reference).} One sample from $\pi$ with thinking on and the model's default sampling, exactly as
the benchmark prescribes.

\paragraph{\sel{}: the System One model chooses the turn.} The LLM samples $K{=}5$ turns $a_t^{(1)},\dots,a_t^{(5)}$
i.i.d.\ from $\pi$ in one request. Exact duplicates are merged. The System One model reads the state and the distinct
turns, rendered as tool calls with full arguments, and returns a probability for each; the most probable turn is
executed. It never sees the LLM's reasoning, so it judges actions, not rationales. A uniform pick among $K$ i.i.d.\
samples has the same distribution as \llm, so any difference between the two comes from \emph{which} sample is chosen.

\paragraph{\tool{}: the System One model chooses the kind of action.} The System One model reads the state and the
full tool menu (each tool's name and description, plus \textsc{finish}) and picks one. The LLM then writes the turn
with every tool still in its prompt but its calls constrained to the chosen tool. The System One model now sets the
agent's strategy and timing (when to gather, when to order, when to document, when to stop) and the LLM supplies the
content.

\paragraph{\ctl{}: a control for \tool.} \tool{} also restricts each turn to one kind of tool, whereas the LLM usually
batches several lookups. \ctl{} applies the same restriction with the LLM choosing: it samples its turn as usual and
keeps only the calls of the turn's first tool.

\paragraph{Fair inputs.} Options are named by letters shuffled with a seed per task, run and step. The System One model
reads a deterministic 32k-token view of the state (oldest tool results shortened first); the LLM reads up to 128k
tokens. If the System One model fails, the first sample is executed; this happened \DECSelerr{} times in the
\sel{} run.

\section{Setup}\label{sec:setup}

\paragraph{PhysicianBench} \citep{physicianbench2026} adapts 100 real outpatient consultations from 21 specialties
into long-horizon tasks on a FHIR server with the records of 108 de-identified patients (47k conditions, 114k
observations, 35k procedures, 13k medication requests, 2.3k clinical notes). Each task has 5--9 checkpoints (670 in
total) of four types: data retrieval (DR), clinical reasoning (CR), action execution (AE: orders, prescriptions,
referrals placed in the record and verified by code) and documentation (Doc). A task passes only if all of its
checkpoints pass. We use the released harness: a fresh server and database per task, the MiniAgent loop with parallel
tool calls and at most 100 steps, and the task's pytest graders.

\paragraph{ClinEnv} \citep{clinenv2026} turns MIMIC-IV admissions \citep{johnson2023mimiciv} into staged episodes. At
each stage the agent questions simulated patient, nurse, lab and history agents, then submits medications, procedures
and diagnoses, scored against the recorded decisions with ontology-aware matching. Every submission can be checked
against gold, which makes ClinEnv our instrument for step-level analysis. We use the authors' 392 released admissions
scored by all seven models in their paper.

\paragraph{Models.} The LLM is Qwen3.8-27B \citep{qwen38} in bf16 with 128k context and thinking on, served by vLLM
\citep{kwon2023vllm}. The System One model is Clef-27B \citep{clef2026} with its native joint head. The PhysicianBench
judge is the same Qwen model with thinking off, shared by all arms. Everything runs on one node with four H100 GPUs;
no record leaves it (\S\ref{sec:ethics}).

\paragraph{Statistics.} Arms are compared on the tasks both completed. We report differences with 95\% bootstrap
intervals over tasks (10,000 resamples) and exact McNemar tests for task success.

\section{Results}

\subsection{Choosing among proposals, the System One model matches the LLM}\label{sec:select}

Table~\ref{tab:main} and Figure~\ref{fig:main} give the headline. \sel{} passes \PBcpSel\% of checkpoints against
\PBcpLLM\% for the LLM ($\Delta$ \PBdiffSel{} points in task success, McNemar $p\PBpSel$). Over all
\PRSelLLMn{} tasks both have completed, the difference stays within a point (\PRSelLLMcp{} on checkpoints). It is not
a wash, though: the two deciders behave differently. The System One model departs from the LLM's own first sample at
\DECSeldepart\% of steps with a real choice and reaches the same quality with fewer calls
(\TLCallsSel{} versus \TLCallsLLM{} per task). Its profile shifts toward action: action execution
\PRSelLLMAE{} and data retrieval \PRSelLLMDR{} points, documentation \PRSelLLMDO{}.

\subsection{It acts when action is required}\label{sec:act}

Why does action execution improve? Every step of the \sel{} run logs the five proposals and the System One model's
probabilities, so each order step can be scored against the orders the task's graders require
(Figure~\ref{fig:orders}). Over \ONsteps{} order steps in \ONtasks{} tasks, two kinds of step stand out. When one of the
proposals places a required order, the System One model chooses an ordering turn \ONReqclef\% of the time, although
only \ONReqshare\% of proposals order and the LLM's own first sample orders in \ONReqfirst\% of these steps. When no
proposal places a required order, it orders in \ONNoneclef\% of steps. On the \ONdisc{} steps that mix right and other
proposals it picks a right one \ONclefAcc\% of the time (random \ONrandAcc\%, first sample \ONfirstAcc\%, candidate
AUROC \ONauroc). The LLM often proposes the right order and then, sampling, fails to place it; the System One model
recognises it.

\subsection{Steering alone, it stops gathering data}\label{sec:steer}

Given the tool menu instead of proposals, the same model fails. \tool{} passes \PBpassTool\% of tasks and
\PBcpTool\% of checkpoints ($\Delta$ \PBdiffTool{} points in task success, $p\PBpTool$), and its data-retrieval
checkpoints collapse first. Figure~\ref{fig:tools} shows why: it retrieves \TLRetTool{} times per task against the
LLM's \TLRetLLM{}, and it writes the note \TLDocTool{} times, rewriting it again and again instead of finishing. The LLM
disagrees with its tool choice often enough that \TOOLregen\% of steps must be regenerated with the tool named.

The control settles where the loss comes from. Restricting the LLM to one tool per turn costs nothing measurable: \ctl{} differs
from \llm{} by \PRCtlLLMcp{} points on checkpoints over \PRCtlLLMn{} tasks. Handing the same restricted choice to the System
One model costs \PRToolCtlcp{} points (\tool{} versus \ctl{}, \PRToolCtln{} tasks; task success
\PRToolCtlx\% versus \PRToolCtly\%, $p\PRToolCtlp$). The tools it picks explain the gap (Table~\ref{tab:toolchoice}):
it chooses to write the note at \TCwriteClef\% of steps, where the LLM does so at \TCwriteLLM\%, and it spends
\TCsearchClef\% of its steps on lookups against the LLM's \TCsearchLLM\%. Deciding \emph{when} the evidence is
sufficient is exactly the judgment the System One model lacks.

\subsection{Selection is bounded by what the proposer samples}\label{sec:diversity}

A selector can only add value where the proposals differ. ClinEnv lets us check every proposal against gold. In
\CECases{} admissions run with \sel, the five proposals are distinct strings at \CEDistinctRaw\% of submit steps,
because each submission carries a free-text rationale. Mapped to diagnosis and drug codes with ClinEnv's own matcher,
\CEOneDecision\% of these sets hold a single clinical decision, and only \CERealChoicePct\% contain both a right and a
wrong one (Figure~\ref{fig:clinenv}a). On PhysicianBench, where a turn bundles several calls, proposals differ far more
often (\DECSelsem\% of steps).

To probe discrimination directly we replay the states of an LLM run exactly, render every proposal as action plus
canonical name, and where all are wrong, replace one by a gold decision rendered the same way. Every set then holds
one right answer among two. Both deciders pick the proposer's option: the System One model chooses gold in
\COinjClef\% of \COinjN{} sets and the LLM in \COinjSel\% (Figure~\ref{fig:clinenv}b). Shown only the options, the
System One model chooses gold more often (\COinjBlind\%). The state is the LLM's own trajectory, whose questions and
lab orders gather evidence for its working hypothesis; a decider that reads it follows that hypothesis. Step-level
gold injection inside an agent's trajectory therefore measures agreement with the trajectory more than clinical
discrimination, a pitfall for any step-wise evaluation of agents.

\section{Related work}

\paragraph{Choosing among samples.} Majority voting over reasoning paths \citep{wang2023selfconsistency}, trained
verifiers \citep{cobbe2021verifiers}, process reward models \citep{lightman2024verify} and LLM judges
\citep{zheng2023judge} all pick among sampled outputs. \sel{} applies best-of-$K$ selection at every step of an agent
loop, with a decision model as the selector.

\paragraph{System One decision models.} JEV introduced the typed-question interface \citep{typesafe2026jev}; Clef is
an open 27B model with a joint head over a Qwen3.8-27B backbone \citep{clef2026}. As judges they approach frontier
LLMs on verdicts that can be read off the input at a small fraction of the cost \citep{li2026jevjudge}; as next-action
selectors in general agents, most of their wrong actions follow a correct reading of the state \citep{li2026reading}.
We bring them into clinical agents and separate choosing an action from steering.

\paragraph{Clinical agent benchmarks.} PhysicianBench grades long-horizon physician tasks in a live record system by
code and rubric \citep{physicianbench2026}; ClinEnv evaluates staged inpatient decisions against MIMIC-IV
\citep{clinenv2026,johnson2023mimiciv}. Both have been run only with generative LLM agents.

\section{Discussion}

\paragraph{A division of labour.} The LLM is good at what the System One model cannot do: deciding what to look up,
how much evidence is enough, and writing the note. The System One model is good at what the LLM does unreliably:
committing to the right concrete action once it is on the table. \sel{} combines the two and loses nothing in
checkpoint quality. \tool{} hands the System One model the part it is worst at.

\paragraph{Cost.} The System One decision itself is one forward pass, about \DECSels{} s per step on one GPU, and adds
no generated tokens. The cost of \sel{} lies in the five proposals (\TOKSel{} versus \TOKLLM{} generated tokens per
task). Cheaper proposers, fewer proposals when they agree, or proposals targeted at decision steps would reduce it;
the System One model never needs to reason in text.

\paragraph{What would make selection stronger.} Proposals that differ in substance, not wording: when the five
samples are one decision, no selector can help (\S\ref{sec:diversity}). Diversity-seeking proposal schemes are the
natural next step.

\section*{Limitations}

We study one LLM. Our main System One model, Clef-27B, shares its backbone; the five other System One models (\S\ref{sec:deciders}) are evaluated on a growing exam and, for one of them, online, so their results are preliminary. The
PhysicianBench numbers come from one run per arm, and the \ctl{} control covers the \PRToolCtln{} tasks it shares with
\tool; repeated runs (pass@3) are in progress. Our judge is the local LLM rather than the
leaderboard's, so absolute scores are not comparable with the leaderboard, while every arm shares the judge. The System
One model reads a 32k-token view of states the LLM reads in full. ClinEnv enters as a step-level instrument; its
online runs were paused to complete PhysicianBench.

\section*{Ethics and data}\label{sec:ethics}

PhysicianBench's records are real de-identified patients under a data use agreement, and ClinEnv derives from MIMIC-IV,
which forbids sending records to services without verified zero retention. All models run locally, a socket guard
blocks any non-local connection from agent and grader processes, and trajectories and notes stay on access-controlled
storage outside version control. We report aggregates only. ClinEnv's code has no license file at the version used;
we use it for research reproduction.

\section{Decision interface}\label{app:interface}

\paragraph{Questions.} The System One model receives the state and one Choice question. For \sel{}: \emph{``The state
shows a clinical task assigned to an AI agent that works in an electronic health record through FHIR tools, followed
by the agent's actions and their results so far. Each option is a candidate next action for the agent. Choose the
candidate that best advances completing the task correctly, completely and safely.''} For \tool{} the second and third
sentences read: \emph{``Each option is a tool the agent can use for its next action, or finishing with a final answer.
Choose what the agent should do next to complete the task correctly, completely and safely.''} Options are the
rendered turns (\sel) or each tool's name with the first paragraph of its description, plus \textsc{finish} (\tool).
ClinEnv uses the same template with a description of its staged, conversational setting.

\paragraph{State.} The state is the task instruction followed by every step: the action, rendered as tool calls with
full arguments, and its results as the LLM saw them. It is fitted into the System One model's 32,768-token context
deterministically: tool results are kept in full, then shortened oldest-first to 800 characters, then omitted
oldest-first, each by the smallest number that fits. In the \sel{} run \DECSelshort\% of decisions saw shortened
results and \DECSelomit\% saw omitted ones.

\paragraph{Other System One models.} pplx-decider-v1.2 (\texttt{cce0f3f8}), d3 v3.1.0 (\texttt{cbff3a3c}), linne-oak-1.0 (\texttt{20da7bf3}), amos-1-large (\texttt{d67e051c}) and decider-31b (\texttt{e12ddf20}) each run their authors' own serving code on one H100, locally and offline. pplx-decider-v1.2 ships a library only, which we call on its reference path. decider-31b is NVFP4, which an H100 runs through vLLM's weight-only FP4 path; its authors used Blackwell GPUs. Every model receives the state and question built for Clef, with the same fitting rule, counted in its own tokenizer.

\paragraph{The LLM.} Qwen3.8-27B with thinking on, temperature 1.0, top-$p$ 0.95, top-$k$ 20, at most 16,384 completion
tokens per call. Two identical replicas serve all arms (one with tensor parallelism over two GPUs); each task is routed
whole to the less loaded replica, independent of the arm.

\section{Step-level evaluation on ClinEnv}\label{app:clinenv}

\paragraph{Items.} A submit step is a step whose proposals are all submissions of one type. Each proposal is scored
against the stage's gold decisions of that type that earlier executed submissions have not yet matched, with
ClinEnv's pair scores (ICD retrieval and re-ranking with hierarchical F1 for diagnoses and procedures; ATC hierarchy
with an action gate for medications); a proposal is right if its score is at least 0.5.

\paragraph{Canonical and injected sets.} Each proposal is rendered as action plus canonical name (the ICD title of its
mapped code, or the ATC-normalised drug name), without the rationale argument, and duplicates are merged. Where no
option is right, one wrong option, chosen with a seed, is replaced by an open gold decision rendered the same way; a
single wrong option gets the gold one added. States are replayed exactly from an append-only message log.
